# AGENTS.md — trading-office

Часть экосистемы `trdlabs`. Кросс-репозиторные вопросы — архитектура, контракты, раскатка,
локальный стек — из [`../control-center/AGENTS.md`](../control-center/AGENTS.md): там канонический
порядок чтения и карта владения. Соседа рядом нет (отдельный клон) — работать по локальным документам.

## Что это

Визуальная диспетчерская для агентных торговых систем: pixel-art «офис», где каждый агент —
спрайт за столом с живым статусом. Пульт наблюдения и управления поверх других систем, не
самостоятельная торговая система.

**Офис выражает намерение, но НЕ исполняет.** Любое действие уходит запросом на write-endpoint
платформы, которая сама валидирует, клампит, допускает и исполняет. Вся политика — server-side.

- **Можно:** читать состояние (Ops / Research Read) и слать запросы-намерения на платформенные
  write-endpoints (промоушен риск-профиля — платформа зажмёт его в guardrails и прогонит admission).
- **Нельзя:** принимать торговые решения, обходить гейты платформы, писать напрямую в её БД,
  встраивать execution-логику в офис.

## Гейты

```bash
npm run typecheck && npm run test
npm run verify:assets    # ассеты этажа синхронны
```

Подключение к mock-платформе без правок кода — через окружение:
`OFFICE_CONNECTOR_MODE=trading-lab`, `OFFICE_PLATFORM_ENABLED=true`,
`TRADING_PLATFORM_READ_URL`, `TRADING_PLATFORM_READ_TOKEN`.

## Правила и грабли

- Данные для чтения — только с read-поверхностей; истина по исполнению и данным на `platform`.
- Действия оператора требуют authZ, аудит-след и подтверждение — переиспользовать
  `operator-auth` и `operator-confirmation`; идемпотентность запроса на стороне вызова.
- Общий код выносить в `packages/`, границы workspaces не размывать.
- Документация и уточняющие вопросы — на русском.
